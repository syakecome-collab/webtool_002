# 広告収入で成立させるには何を作るべきか（リサーチと結論）

調査日: 2026-09-10 / 目的: 広告収入。前提: Claude が完成まで一貫して実行できること、メンテナンス負荷が低いこと。

## 0. 結論

1. **「広告単価が高い ∧ 主役がいない」はほぼ矛盾する。** 単価が高いのは送客先が儲かる分野で、そこには必ず企業がツールを置いている。実際、候補を 4 つ潰した（後述）。
2. **記事で広告を稼ぐ道は 2026 年に閉じた。** AI Overviews 表示時、1 位のクリックが平均 58% 減。
3. **残っているのは「入力しないと答えが出ない」「成果物がファイルで手元に残る」もの。** AI に横取りされない。
4. **1 本のホームランではなく、長尾ツールの物量で積む。** これが唯一、Claude という道具の形に合った勝ち筋。人間には物量的に無理で、企業には採算が合わない。

---

## 1. 広告収入の現実（まず数字）

| 指標 | 実測値 | 出典 |
|---|---|---|
| 雑記ブログの RPM | **250〜350 円 / 1,000PV** | [ym-life](https://ym-life.com/adsense-rpm/), [nobutoblog](https://nobutoblog.com/page-rpm/) |
| 月 100 万円達成時の PV | **422 万 PV/月** | [個人開発で月収100万](https://note.com/codemesi/n/n122513c4a453) |
| 高単価ジャンルの CPC | 金融・保険・法律・不動産で **500〜3,000 円**（最大 5,000 円超） | [キャラIPラボ](https://note.com/character_ip_lab/n/n640b01ead509), [jiyoujin](https://jiyoujin.com/adsense-high-paying-niches/) |

**月 10 万円に必要な PV**
- 雑記系 RPM 250 円 → **40 万 PV/月**
- 高単価ツール RPM 1,000〜2,000 円 → **5〜10 万 PV/月**

→ **単価の低い分野を選んだ時点で、必要 PV が 4〜8 倍**になる。ここが最初の分岐。

## 2. 追い風と向かい風

### 向かい風: AI Overviews
- AI Overviews が出ると 1 位のクリックが **平均 58% 減**（Ahrefs 2026年2月）、別実験でも **38% 減**
- AI Overviews の表示率は 2025年1月 6.49% → 2026年Q1 **25.11%**
- 出典: [ウェブロード](https://www.webroad.co.jp/archives/65060), [KeywordFinder](https://keywordfinder.jp/blog/seo50_aio_seo/), [JADE](https://blog.ja.dev/entry/blog/2026/04/30/traffic-decline-not-always-ai)

**含意:** 「◯◯とは」「◯◯の方法」に答える記事は、書いた瞬間に AI に要約されて終わる。**逆に、AI が肩代わりできないのは「ユーザーが自分の値を入れて初めて答えが出るもの」と「ファイルとして手元に残る成果物」**。ここだけが安全地帯。

### 向かい風: AdSense 審査
- 審査落ちの **8 割超が「有用性の低いコンテンツ」**
- **AI 全自動の記事だけでは通りにくい**（体験談・一次情報の付加が要るとされる）
- 出典: [Tsuzuki Blog](https://www.tsuzukiblog.org/google-adsense-screening/), [zio-start](https://zio-start.com/archives/google-adsense-7point/)

**含意:** ツールだけのペラサイトは通らない。ただし**ツールそのものは「独自の有用性」**なので、各ツールに実用的な解説を添えれば通しやすい。

## 3. 「主役不在」を探して、4 つ潰した記録

| 候補 | 需要 | 結果 | 既にいた主役 |
|---|---|---|---|
| 育休・産休の手取り計算 | 高（制度改正で複雑化） | ✗ | [社労士クラウド](https://sharoushi-cloud.com/ikujigo/)、[育休シミュレーター](https://ikukyu.tokyo-jp.org/)、[デイライト法律事務所](https://www.komon-lawyer.jp/ikukyu/) ほか多数 |
| 年収の壁の判定 | 非常に高（[7 つの壁が並立](https://taxlabor.com/nenshu-kabe-2026-178man/)、2026年4月に判定基準も変更） | △ | [shakui-tools](https://shakui-tools.com/nenshu-kabe)、[最速資産運用](https://ma-bank.net/tool/tax_kabe/)。記事は飽和、ツールはまだ隙あり |
| 高額療養費の上限額 | 高（[2026年8月から引き上げ](https://www.freee.co.jp/kb/kb-trend/high-cost-medical-care-benefit/)、2027年8月に細分化） | ✗ | [価格.com 保険](https://hoken.kakaku.com/gma/select/high-cost/self-pay/)。保険送客の大手が押さえている |
| シフト表・当番表の自動作成 | 中〜高 | ✗ | [シフト屋さん](https://shiftyasan.com/)、[Canva](https://www.canva.com/ja_jp/features/shift-scheduling-app/) |

**そこから見えた法則:**
> 広告単価が高い分野 = 送客先（保険・金融・士業）が儲かる分野 = **企業が無料ツールを置いて客を待っている分野**。
> つまり「単価が高くて主役がいない」場所は、探しても構造的にほとんど無い。

**逆に主役がいないのは、企業が 1 本ずつ作っても採算が合わないほど細かいところ。** 例えば方眼紙・原稿用紙は今も個人サイト（[方眼紙ネット](https://houganshi.net/genkouyoushi.php)、[家勉キッズ](https://ieben.net/hougansi/)）が握っていて、作りは古くスマホ最適化もカスタマイズもされていない。

## 4. だから、勝ち筋はこれ

### 戦略: 長尾ツールの物量で積む

**1 本のホームランを狙わない。** 月 1,000〜10,000 PV のツールを 100 本作って 1 ドメインに束ねる。

なぜこれが Claude 向きか:
- **物量が唯一の差別化になる。** 人間の個人開発者は 1 本に数週間かかる。企業は 1 本あたりの採算で判断して降りる。**大量生産だけが空いている**。
- **メンテ 0 に寄せられる。** 制度に依存しない計算・生成だけを選べば、作ったら放置できる。
- **API コスト 0。** ブラウザ内で完結させれば、広告収入がそのまま粗利。逆に LLM API を使うツールを無料公開すると、PV が増えるほど赤字になる。
- **AdSense 審査に有利。** 100 個の実際に動くツール = 「独自の有用性」そのもの。

### 選ぶべきツールの 4 条件

1. **入力しないと答えが出ない**（AI Overviews に横取りされない）
2. **成果物がファイル / 印刷物で残る**（同上、かつ再訪する理由になる）
3. **制度・外部 API に依存しない**（メンテ 0）
4. **ブラウザ内で完結する**（コスト 0、プライバシー訴求にもなる）

### テーマ候補

| 案 | 中身 | 単価 | 競合 | メンテ |
|---|---|---|---|---|
| **A. 印刷・書式ジェネレータ群** | 方眼紙、原稿用紙、名簿、当番表、席次表、賞状、のし、時間割、記録シート | 低（RPM 200〜300 円） | 古い個人サイト = **弱い** | **ほぼ 0** |
| **B. アップロードしないファイル処理群** | 画像圧縮・リサイズ、PDF 結合・分割、HEIC 変換、透かし、一括リネーム | 中 | iLovePDF 等が強いが、**全部サーバー送信**。「送信しない」は明確な差別化 | 小 |
| **C. 暮らしの手続き計算機群** | 年収の壁、退職金の税金、残業代、相続分、車の維持費 | **高（RPM 1,000 円超）** | 士業・保険の企業サイトが強い | **毎年必要** |

**推奨は A を主軸に、C を数本混ぜる構成。**
A で「メンテ 0・競合が弱い・量産できる」を取ってドメインを育て、C で単価を補う。B は A が回り始めてから足す。

## 5. 正直に言う: Claude が完結できないこと

| 工程 | 誰がやるか |
|---|---|
| ツールの企画・実装・テスト・記事執筆 | **Claude（全部できる）** |
| ホスティング設定ファイルの用意 | **Claude** |
| 独自ドメインの取得と支払い（年 1,000〜2,000 円） | **人間**（AdSense は独自ドメインが要件） |
| AdSense の申請・本人確認・銀行口座登録 | **人間** |
| Search Console / Analytics の登録 | **人間**（5 分程度） |

技術的な部分は全部こちらで巻き取れるが、**お金と本人確認が絡む 3 工程だけは代行できない。**

## 6. 期待値（正直な見積もり）

```
案 A 主軸で 100 ツール、平均 2,000 PV/月 に育った場合
→ 20 万 PV/月 × RPM 250 円 = 月 5 万円
→ C の高単価ツールを 10 本混ぜて底上げして 月 7〜10 万円

到達までの期間: SEO の立ち上がりに 6〜12 ヶ月（ドメインが育つ時間は買えない）
初期費用: ドメイン代のみ（ホスティングは Cloudflare Pages 等で無料）
```

**月 100 万円は、この方法では届かない**（422 万 PV が必要）。狙えるのは月 5〜10 万円の「放置できる収入」。
そこを目標にするなら、この戦略は現実的に成立する。

# 追記: App Store に出す前提での再検討（2026-09-10）

前提が「Apple の App Store に並べる」「運用実績が欲しい」に変わったため、結論を修正する。

## 7. まず、私がどこまで実行できるか

**Mac は不要だった。** [EAS Submit は macOS / Linux / Windows で動き](https://docs.expo.dev/submit/ios/)、[EAS Build は iOS のビルドもクラウド（Expo 側の Mac）で行う](https://docs.expo.dev/build/introduction/)ので、この環境からでも iOS アプリの一式を作れる。

| 工程 | 誰が |
|---|---|
| Expo プロジェクト一式、全画面の実装、テスト | **Claude** |
| アプリアイコン、スクリーンショット、ストア掲載文、プライバシーポリシー | **Claude** |
| `eas.json` / ビルド設定 / AdMob 組み込みコード | **Claude** |
| **Apple Developer Program 登録**（年 99 ドル ≒ [14,000〜15,000 円](https://www.tekural.com/blog/apple-developer-program-cost)、個人なら Apple ID のみ・承認は 1〜2 日） | **人間** |
| **App Store Connect でのアプリ登録、AdMob アカウント開設**（銀行口座・税情報） | **人間** |
| **`eas build` / `eas submit` の実行**（Apple ID でのログインが要る） | **人間**（コマンドは Claude が用意） |

→ **コードと素材は 100% こちらで巻き取れる。人間の作業はアカウント周りの実質 2〜3 時間**。

## 8. App Store では「100 本のツール群」戦略は使えない

Web での結論（長尾ツールを大量に作る）は、App Store では**ガイドライン違反で弾かれる**。

- **4.2 Minimum Functionality**: 機能が薄いアプリはリジェクト。「Web で 5 分で作れるもの」は通らない。
- **4.3 Spam**: **同一開発者による類似アプリの量産を明確に禁止**。似たツールを 100 本出す行為そのものが対象。
- 2017 年以降この 2 つは継続的に厳格化されている（[リジェクト事例](https://note.com/yuyayamaki/n/ne0243a2e9cc5)、[4.3 Spam の実例](https://www.yurufuwase.com/entry/2023/12/04/190000)、[解説](https://makotton.com/2017/10/24/1594)）。

→ **App Store では 1 本に集中するしかない。** これは Web 戦略との決定的な違い。

## 9. アプリの広告収入の現実（数字）

| 実績 | 収益 | 出典 |
|---|---|---|
| 月間ユーザー **1 万人** / AdMob のみ | **月 8,000 円弱** | [Kazuki Kubo](https://note.com/assaulter/n/nf4c4aafc6500) |
| **10 万ダウンロード** | 月 15〜30 万円 | [SELVA](https://www.selva-i.co.jp/article/archives/1547) |
| 60 万 DL（サブスク＋広告） | 月 250 万円 | [けい](https://note.com/keitaaaan/n/n6b4ff16d9835) |

**含意が 2 つある。**

1. **月 1 万円を超えるには MAU 1 万人以上が要る。** 広告だけで生活費は現実的でない。まず「運用実績」を取り、収益は後から積む順序が正しい。
2. **「1 回使って終わる」アプリは広告と絶望的に相性が悪い。** 計算機・ジェネレータ類は 1 回で用が済むので、DL されても広告表示がほぼ発生しない。
   → **毎日ないし毎週開く理由があるアプリでなければならない。** これが App Store 版の最重要制約で、Web の「ツール群」とは逆の設計になる。

## 10. 2026 年の App Store で個人開発が当たっている型

[個人開発アプリの定点観測](https://note.com/kawakijourney_ai/n/nae43fd3cf881)によると、2026 年に目立つのは
**職業特化 / 推し活 / 筋トレ / AI 記録 / 学習 / 家計簿 / 趣味管理**。
大きな SNS や万能ツールではなく、**日常の小さい面倒をアプリ化したものが強い**。

特に示唆的なのがこの一節。

> 職業特化アプリは個人開発で参考になり、タクシー以外にも配達員、営業、フリーランス美容師、整体師、夜職、講師、ハンドメイド作家などに横展開できる。
> **汎用管理アプリにしないで、その職業の人が毎日見る数字に絞る方が刺さる。**

これは今回の条件と噛み合う。

| 条件 | 職業特化の「その日の数字」アプリ |
|---|---|
| 毎日開く | ◎ 仕事のたびに記録する |
| 主役がいない | ◎ 汎用家計簿はあるが、職業特化はどれも薄い |
| サーバー不要・API コスト 0 | ◎ 端末内 DB で完結 |
| メンテ 0 | ◎ 制度にも外部 API にも依存しない |
| 4.2 を通せる | ◎ 記録・集計・グラフ・書き出しがあれば十分な機能量 |
| 広告単価 | ◯ 車・バイク・保険・求人・カードなど、単価の高い広告が当たる読者層 |

## 11. 修正後の結論

- **Web = 長尾ツールの物量。App Store = 1 本に集中。** 同じ戦略は使えない。
- **1 本目の目標は収益ではなく「審査を通して運用実績を作ること」。** 収益は MAU が乗ってから。
- **狙うべきは「特定の職業の人が、毎日、自分の数字を見るために開くアプリ」。**
