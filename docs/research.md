# ポスター撮影 → カレンダー一括登録：競合調査と収益化の検討

調査日: 2026-09-10

## 0. 結論（先に3行）

1. **「ある」。しかも飽和しかけている。** 日本にも海外にも同じ機能のアプリが 10 本以上あり、TimeTree のような大手も 2023 年から実装済み。
2. **最大の競合は他社アプリではなく OS 標準機能。** iOS 26 のスクリーンショットからの「カレンダーに追加」が無料で入ってきており、「撮る→予定になる」という機能そのものは、単体では課金理由にならなくなりつつある。
3. **勝負どころは「読み取り」ではなく「読み取ったあとの面倒」。** 家族への共有、持ち物・締切のリマインド、複数人カレンダーへの一括反映、主催者側からの配布。収益化はここに寄せるのが現実的。

## 1. すでにあるもの

### 1-1. OS 標準（無料・プリインストール＝最強の競合）

| 機能 | 提供 | 内容 |
|---|---|---|
| Add to Calendar | iOS 26 / Apple Intelligence | 日時が写ったスクリーンショットを撮ると「カレンダーに追加」が表示され、日時・場所を自動入力（[months](https://months.jp/498/), [9to5Mac](https://9to5mac.com/2026/03/05/ios-26-gives-apples-calendar-app-a-convenient-new-advantage/)） |
| Visual Intelligence | iOS | カメラをかざした対象から情報抽出（[まとめ記事](https://mobilelab.jp/ios-26-matome)） |
| Google Lens / Gemini | Android | 画像内テキスト認識からカレンダー登録への導線 |

**意味するところ:** 「1 枚のポスターを 1 件の予定にする」だけの機能は、iPhone/Android を使っている限り追加インストール不要になった。ここを主戦場にすると価格 0 円の相手と戦うことになる。

### 1-4. 「一括登録」側（自分で作った予定表をまとめて入れる）

- Google カレンダー標準の **CSV / iCal インポート**（[ヘルプ](https://support.google.com/calendar/answer/37111?hl=ja)、[解説](https://saiseich.com/service/googlecalnedar_import/)）

## 2. まだ空いているところ（差別化の仮説）

競合が薄い順に。

1. **主催者・配布側（B2B）が手つかず。**
   受け取る側のアプリは飽和だが、「ポスターや PDF を作る側が、読み取られる前提のデータを添える」側は空いている。自治体の広報紙、学校のおたより、商店街のイベント、ライブハウスのスケジュール。AddEvent（[$29〜$99/月](https://www.saasworthy.com/product/addevent/pricing)）が英語圏でこの市場を取っているが、**日本語・紙前提のワークフローに対応した競合はほぼいない。**
2. **複数人・複数カレンダーへの一括反映。**
   個人アプリは「自分のカレンダーに 1 件」で終わる。部活・PTA・チーム・シフトのように「同じ予定を 20 人に配る」用途は GAS ツールに逃げている（＝プログラミング前提）。
3. **紙 1 枚に複数日程が並ぶケースの精度。**
   年間行事予定表、部活の月間予定、施設の休館日カレンダー。1 枚から 30〜40 件を、行と列の対応を崩さずに取り切れるかは実力差が出る。TimeTree・Calendara が既に狙っている領域だが完成度は割れる。
4. **アプリを入れさせない導線。**
   ブラウザだけで完結し、URL を送れば誰でも使える形（＝今回作った実装の方針）。App Store 審査もインストール障壁もない代わりに、リピート利用の獲得は難しい。
5. **和暦・「第 2 土曜」・「毎月」・開場/開演の区別**など日本語固有の書式。ここは英語圏アプリが構造的に弱い。

## 3. 収益化の可能性

### 3-1. B2C 直接課金（推奨度：低〜中）

- 相場は月 300 円〜$5、年 3,000 円〜$40。
- **無理筋な理由:** OS 標準が無料で同等機能を提供し始めた。単機能アプリの ARPU は下がる方向。
- **やるなら:** 無料枠（月 10 枚まで）＋ 有料（無制限・家族共有・履歴）のフリーミアム。買い切り 600〜1,200 円は AI 原価が継続的に発生するため相性が悪い（サブスク前提にすべき）。

### 3-2. B2B / B2G（推奨度：高）

| 顧客 | 課題 | 課金形態 | 価格イメージ |
|---|---|---|---|
| 自治体・公民館・図書館 | 広報紙やチラシの予定を、住民のカレンダーに載せたい | 年間契約 | 年 10〜50 万円 |
| 学校・園・学童 | 年間行事予定の配布、変更連絡 | 校数課金 | 月 5,000〜3 万円/校 |
| イベント主催・ライブハウス・劇場 | 「カレンダーに追加」ボタン、購読カレンダー配布 | SaaS | 月 3,000〜3 万円（AddEvent 相当） |
| 商業施設・ジム・スクール | 講座スケジュールの一括配信 | SaaS | 同上 |

**この筋が良い理由:** 相手は「1 件登録の手間」ではなく「参加者に来てもらえないこと」に金を払う。無料の OS 機能は競合にならない。1 契約の単価が B2C の 100 倍以上。

### 3-3. 埋め込み・OEM（推奨度：中）

- 抽出エンジンを API として提供（画像 → 予定 JSON）。既存の家族アプリ・グループウェア・名刺管理・プリント管理アプリに組み込む。
- 従量課金（1,000 枚あたり ◯◯ 円）。原価は Gemini Flash クラスなら**画像 1 枚あたり 1 円未満のオーダー**なので粗利は取りやすい（実際の単価は使用モデルの最新価格で要確認）。

### 3-4. 送客・アフィリエイト（推奨度：低）

- 抽出したイベントに対してチケット購入・地図・交通手段のリンクを添える。
- 単価は低く、量が必要。個人開発では現実的でない。

### 3-5. 現実的なユニットエコノミクス（B2C の場合）

```
想定: 月額 300 円 / 無料枠 月 10 枚 / 有料ユーザーは月 60 枚利用
原価:  画像 1 枚 ≒ 0.1〜1 円（Vision モデル）→ 月 6〜60 円
粗利:  240〜294 円/人月（決済手数料・ストア手数料 15〜30% 前引き前）
→ 課金者 1,000 人で月商 30 万円。生活費を賄うには課金者 3,000〜5,000 人が必要。
   飽和市場でこの人数を無広告で集めるのは、率直に言って厳しい。
```

対して B2B は、**10 契約 × 月 3 万円で同じ売上**になる。個人・小規模での勝ち筋は明確に B2B 側。

## 4. リスク

| リスク | 深刻度 | 対応 |
|---|---|---|
| OS 標準機能に飲み込まれる | 高 | 単機能勝負を避け、共有・配布・リマインドに価値をずらす |
| 抽出精度のクレーム | 中 | 「必ず確認画面を挟む」設計にする（自動登録しない）。今回の実装もこの方針 |
| AI 原価の変動 | 中 | 枚数制限・軽量モデル併用・ローカルパーサでの前処理 |
| 個人情報（おたより＝児童名が写る） | 高 | 端末内処理＋送信先の明示、B2G ではデータ保存しない設計が必須 |
| Google API の規約・OAuth 審査 | 中 | まずは .ics / CSV 経由にすれば OAuth 審査を回避できる（今回の実装の選択） |

## 5. この調査を踏まえた実装方針

同梱の実装（`index.html` 他）は、以下の判断でこうなっている。

- **アプリではなく Web ツール。** インストール不要、URL を送るだけ。App Store の審査も更新も不要。
- **OAuth を取らない。** Google カレンダーへの書き込み権限を要求すると審査と信頼のコストが跳ね上がるため、`.ics` / CSV / 登録画面 URL の 3 経路で「一括登録」を実現。iPhone・Android・Outlook でもそのまま使える副次効果がある。
- **AI 無しでも動く経路を持つ。** テキスト貼り付け → 和暦・全角・「1/5〜1/7」対応のローカルパーサ。API キーを持たない人でも価値がある＝入口が広い。
- **必ず確認・修正画面を挟む。** 精度クレームを設計で回避する。
- **鍵はユーザーの端末に置く。** サーバーを持たないので、運用コストゼロ・情報漏えいリスク最小。

次に伸ばすなら、B2B 側（主催者が予定表 URL を配る／購読カレンダーを発行する）が最も筋が良い。
